# Emulator injection licensing review

Reviewed 2026-09-16; distribution policy updated 2026-09-17 for PR #107 and local changes based on `54a221b549c3250749dee9450648bb6610684f04`. This records technical evidence, primary license guidance and the project's distribution decision. It does not manufacture missing upstream permission or exact source provenance.

## Adopted distribution policy

**Retain MIT for original Expo contributions and the applicable licenses and notices for incorporated dependencies.** The earlier blanket agent-plus-emulator combined GPL classification was a conservative project assumption, now superseded by the narrower technical findings below. It was not an established requirement to distribute all QEMU source. The emulator binary and system images are not shipped by this package. Whether the injected library forms a combined work with GPL-covered parts of a particular host remains unresolved. [FSF plugin guidance](https://www.gnu.org/licenses/gpl-faq.en.html#GPLAndPlugins).

**Do not assign a blanket GPL version to the shipped binaries.** The SDK attributes GPLv2-only QEMU to the host and GPLv2-or-later FFmpeg to the renderer, but which host components belong in the legally relevant scope has not been established. If that scope includes independently GPLv2-only code, FFmpeg's later-version option cannot upgrade it. The complete [GPLv2 text](../LICENSES/elfutils/COPYING-GPLV2) is retained as a dependency license text; its presence does not classify both Expo binaries as GPLv2.

The remaining decisions concern the justified host scope, licenses of actual incorporated components, and matching source/relink materials required for distribution. They are recorded in [sources/compliance.json](../sources/compliance.json). Release remains blocked by unresolved entries; development source archives may still be prepared.

## Technical evidence

| Boundary | Evidence and significance |
| --- | --- |
| Injector → target process | [inject.cpp](../src/inject.cpp) calls `frida_injector_inject_library_file_sync` with a user-supplied PID and `poc_agent_main`. It does not call QEMU or gfxstream APIs. |
| Injected agent → renderer | [gum-agent.cpp](../src/gum-agent.cpp) locates `libgfxstream_backend.so`, hooks `FrameBuffer::Impl::postImpl`, and replaces GL functions for readback auditing. |
| Capture → renderer internals | [capture.cpp](../src/capture.cpp) resolves private mangled C++ methods with `dlsym`, exchanges `unique_ptr`/`shared_ptr` objects, uses RTTI, and reads private fields at offsets `0x30` and `0x40`. It shares locks, EGL context state and GPU textures. |
| Capture → its own dependencies | [build.mjs](../scripts/build.mjs) statically links FFmpeg and Frida Gum, with libc++ selected to match the emulator ABI. Expo's separate FFmpeg build has GPL, version3 and nonfree disabled. |
| Agent → external consumers | Status and encoded H.264 travel over sockets. This separates the controller/output consumer, while capture and its renderer integration share the target process. |

The direct renderer calls target gfxstream's Apache-noticed [FrameBuffer implementation](https://github.com/google/gfxstream/blob/8764af0869eb5d3cce3a3e0b9a03545c9301bfc2/host/frame_buffer.cpp), not QEMU CPU internals or the emulator's FFmpeg API. The adapted [BorrowedImage](https://android.googlesource.com/platform/hardware/google/gfxstream/+/35d53baaa71ec845d4e616dc7a31cc7d8d5f640b/host/BorrowedImage.h) and [BorrowedImageGl](https://android.googlesource.com/platform/hardware/google/gfxstream/+/35d53baaa71ec845d4e616dc7a31cc7d8d5f640b/host/gl/BorrowedImageGl.h) declarations also carry Apache notices, which are retained. The hook attaches an entry listener and lets the original function run. Private C++ interfaces and layout offsets create gfxstream ABI dependencies; they do not by themselves establish a dependency on all QEMU code.

The [standalone prototype](../prototypes/gfxstream-hook/README.md) used the existing injector and a minimal Gum agent to observe real `postImpl` calls in an unmodified standalone gfxstream build without QEMU or Android Emulator. This proves entry-hook independence, not portability of the complete GPU capture path. Apache-2.0 excludes merely linking or binding by name to interfaces from its own derivative-work definition. This supports the narrower boundary but does not waive terms of other components in Google's SDK renderer or decide its combined-work scope. [Apache-2.0 §§1, 4](https://www.apache.org/licenses/LICENSE-2.0), [source-boundary evidence](gfxstream-hook-source-boundary.md).

Frida also places bootstrap/loader code in the target: the pinned [helper backend](https://github.com/frida/frida-core/blob/0602e5dca4c9d7be6098fc319edf978724dabeab/src/linux/frida-helper-backend.vala#L898-L923) writes loader bytes, and the [loader](https://github.com/frida/frida-core/blob/0602e5dca4c9d7be6098fc319edf978724dabeab/src/linux/helpers/loader.c#L106-L151) opens the capture library and invokes its entrypoint. Audit these bytes separately. The standalone injector's entire libelf/OpenSSL dependency list does not automatically become part of the target.

This establishes the intended topology from source. The earlier Docker build using upstream prebuilt Frida devkits and its native tests passed. The later Linux offline build regenerated the Frida devkits, built both native outputs, passed native checks, and demonstrated relinking a modified FFmpeg; see [the validation record](linux-source-rebuild-validation.md). Five checked-in Frida helper payloads still lack complete regeneration inputs, as documented in [the payload audit](frida-linux-payloads.md). GPU capture and live emulator process mappings have not been tested; the standalone demo did record its own process mappings.

## Exact emulator artifact

Inspected Google's [Linux SDK archive, build 15507667](https://dl.google.com/android/repository/emulator-linux_x64-15507667.zip). Its `emulator/source.properties` identifies version **36.6.11**.

- `NOTICE.csv` attributes GPL-2.0-or-later FFmpeg to `lib64/libgfxstream_backend.so` and GPL-2.0-only QEMU to the host executables. These are vendor attribution records, not a complete verified source manifest.
- The actual renderer contains `--enable-gpl`, `--enable-libx264`, GPL-version-2-or-later license strings for libavcodec/libavutil, and an FFmpeg 4.4.2 version string. This is stronger evidence than the manifest alone that its FFmpeg build is GPL-enabled.
- The notices conflict: `NOTICE.txt` describes FFmpeg as LGPL2.1, while the CSV references a 3.4.5 source archive. Neither describes the observed renderer's FFmpeg build accurately. Do not use those references as proof of matching corresponding source.
- No applicable broad plugin/linking exception was identified in the inspected QEMU/SDK notices or the [public QEMU license statement](https://android.googlesource.com/platform/external/qemu/+/f0c183f1cc7456ecd6f3607f2f47893768ae4334/LICENSE). Frida's wxWindows exception does not grant permission from QEMU or FFmpeg copyright holders.

Renderer entry: `emulator/lib64/libgfxstream_backend.so`, 15,589,408 bytes, SHA-256 `86e21e94fb0c1a6313288549953240289d071e0f9a75a2b5e80495bc97fae30a`. Configuration string offset: 1,840,810; libavutil/license: 1,941,399; libavcodec/license: 2,095,911; version: 3,487,824. Offsets are zero-based bytes in the uncompressed file.

To reproduce, extract that entry plus `emulator/source.properties`, `emulator/NOTICE.csv` and `emulator/NOTICE.txt` from the linked ZIP, then inspect the renderer's printable strings and hash. This review used HTTP byte ranges and ZIP decompression in memory, downloading about 5.4 MB. Supporting extraction scripts, hashes and notes are retained locally under ignored `artifacts/legal-review/`. No exact source revision matching the complete SDK build was established.

## Compatibility decisions

| Decision | Current evidence | What closes it |
| --- | --- | --- |
| Applicable GPL version | Exact SDK attributes GPLv2-only QEMU and GPLv2-or-later FFmpeg; the relevant combined-work scope and complete compiled source set are unverified. | First justify which GPL-covered host components, if any, enter the scope; then determine compatible license options from matching source. Do not infer GPLv2-only from QEMU's presence elsewhere in the host. |
| Apache interfaces and renderer | The adapted descriptors and referenced gfxstream implementation have Apache-2.0 notices; interface linking is excluded from Apache's derivative-work definition. Apache-2.0 is not considered GPLv2-compatible by the FSF. | Preserve Apache notices. Assess the Apache/GPLv2 compatibility question only if a justified scope combines the relevant covered code; document applicable permissions or exclusions. Changing an SPDX label is not a fix. |
| NVIDIA runtime | `capture.cpp` loads `libcuda.so.1`; FFmpeg's NVENC implementation loads `libnvidia-encode.so.1`. Drivers are installed independently. | Inventory generated PTX for any incorporated proprietary material. If the justified scope imposes GPL runtime constraints, assess the applicable version's system-library treatment or permission from the relevant copyright holders. |
| In-target Frida code | Core emits bootstrap/loader machine code in addition to the Gum-linked agent. Injector helpers remain partly unaudited. | Record every emitted payload, its source/build inputs and actual licenses; regenerate them from the supplied sources. Keep the separate controller's dependency analysis separate. |
| Host source scope and provenance | Matching source for SDK build 15507667 has not been found; the vendor's FFmpeg source link is stale. Standalone hooking does not require QEMU. | Establish whether host source is required and justify the module boundary. Match and include any required modules/build inputs, or record evidence supporting their exclusion. Neither all QEMU source nor no host source is established as the answer. |

Apache-2.0's definition excludes separable/interface-linking works from its own derivative-work definition; that is not an exception granted by QEMU or FFmpeg copyright holders. Retaining the interface notices does not settle whether the adapted material is copyrightable, and its small size alone does not settle that either. [Apache-2.0 §§1, 4](https://www.apache.org/licenses/LICENSE-2.0), [Apache GPL compatibility explanation](https://www.apache.org/licenses/GPL-compatibility).

The standalone injector includes LGPLv3-option libelf and Apache-2.0 OpenSSL. Those are not automatically part of the injected program merely because `inject` loads it. If relevant code is found in the injected bootstrap, the selected license options must be assessed there. Frida's wxWindows linking exception does not grant exceptions for third-party dependencies or the emulator. [GNU LGPLv3 guidance](https://www.gnu.org/licenses/license-list.en.html#LGPLv3), [Frida Core terms](../LICENSES/frida-core/COPYING).

If GPLv2 applies to the justified combination, assess NVIDIA using **GPLv2's own section 3 exception**, not GPLv3's different definition. Independent installation and absence from the archive are facts, not a sufficient exception analysis. A copyright holder can grant an additional permission only for code they control; an Expo-only exception cannot cover someone else's GPL code. NVRTC is an external compiler rather than a shipped runtime, and no NVRTC binary is included in the outputs. [GPLv2 text](https://www.qemu.org/license-gpl-2/), [FSF system-library guidance](https://www.gnu.org/licenses/gpl-faq.en.html#SystemLibraryException), [additional-permission guidance](https://www.gnu.org/licenses/gpl-faq.en.html#GPLIncompatibleLibs), [NVIDIA FFmpeg integration documentation](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html).

The Android SDK agreement assigns open-source components to their respective licenses (§3.5). The project does not redistribute proprietary SDK/system-image components. [Android SDK terms](https://developer.android.com/studio/terms).

## Source distribution and rebuild requirements

Provide matching dependency sources and effective rebuild/relink materials alongside each versioned binary, as required by its actual incorporated components. Include preferred source for modifications, patches, relevant interface definitions, generated inputs and build/install scripts; preserve notices and identify modifications. If GPLv2 applies to a justified combined-work scope, use its downloadable corresponding-source route with equivalent access; neither a generic upstream link nor this document is a written source offer. GPLv3's differently worded source-scope provision does not decide a GPLv2 obligation. [GPLv2 §§1–3](https://www.qemu.org/license-gpl-2/).

The user receives full Expo source, so a separately provided object-only relink kit is not inherently required. However, rebuilding must work with modified static LGPL dependencies. For Frida this includes rebuilding its dependency archives, symbol-renamed devkits, and embedded loader/helpers from source, not merely relinking a prebuilt devkit. Matching library source and effective rebuild/relink machinery remain necessary. [LGPL2.1 §6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.en.html), [Frida devkit generator](https://github.com/frida/releng/blob/963fe3826f861a7d844d235957f2f13738e3a73b/devkit.py).

The hook's private-interface usage and the presence of QEMU in a supported host do not by themselves require the whole emulator, SDK or Android system-image source. Conversely, omitting the host binary from distribution does not itself resolve a combined-work question. Record a justified scope, exact source manifests for any required host components and applicable exclusions. Until then, host source scope and matching remain unresolved.

[Rebuilding from source](rebuilding-from-source.md) describes the local Linux and Docker scripts, source archive creation, and dependency-directory overrides. A clean rebuild and a rebuild with changed dependency source validate that those materials are useful; a successful source archive command alone is not proof of licensing compliance. Each stable or canary binary distribution needs its own matching archive, complete inventory and maintained source reference.

## Machine-readable release record

[sources/compliance.json](../sources/compliance.json) is the release input. `distribution.injectedAgentTreatment` records the unresolved host relationship and `intendedCombinedLicense` remains unset. Original Expo code is MIT; the incorporated dependency notices remain applicable. `host` identifies the inspected SDK and verified entry hashes; `archiveSha256` remains null because the whole unshipped SDK was not downloaded. An SDK-wide checksum is not required merely to preserve this bounded evidence.

Each `decisions` entry remains `unresolved` until there is supporting resolution evidence. Its `evidence` list may record findings informing the question; marking it resolved requires the recorded scope analysis, permission or artifact that closes it, not just a generic licensing link. `host.correspondingSource` records the accepted source scope and, when host source is required, a hash of the matching source manifest. The `releaseEvidence` hashes identify the final inventory, clean rebuild and modified-dependency rebuild records. Its source URL must identify the corresponding versioned download and be published with the binaries.

Do not populate missing hashes, source revisions, permissions or conclusions with guesses. The archive tooling can prepare development material now and require these records for a release. The narrower technical boundary does not mark the outstanding dependency, source or host-scope reviews complete.
